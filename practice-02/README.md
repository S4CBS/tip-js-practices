**Исправление эксперимента 2:**
Для возврата значения из стрелочной функции с блочным телом требуется явно указать `return`:
```javascript
const square = (value) => {
  return value * value;
};
// Либо краткая форма записи без фигурных скобок:
// const square = (value) => value * value;
```
После исправления `square(4)` возвращает `16`.

## 4. Модель данных и функции

В приложении задача представлена объектом со следующей структурой:
- `id` — положительное безопасное целое число (`Number.isSafeInteger(id) && id > 0`).
- `title` — строка длиной от 1 до 100 символов после удаления краевых пробелов.
- `completed` — булево значение (`true` или `false`).
- `priority` — строка из фиксированного набора: `'low'`, `'medium'`, `'high'`.

**Контракт операций изменения:**
- Успешный результат: `{ ok: true, tasks: <новый_массив> }` (для `createTask` возвращается `{ ok: true, task: <новый_объект> }`).
- Ошибка валидации или отсутствие данных: `{ ok: false, error: "<описание_ошибки>" }`. Исходный массив и его элементы остаются без изменений.

**Ответы на контрольные вопросы:**
- **Почему `id` не равен индексу:** Индекс зависит от текущего положения элемента в массиве и сдвигается при удалении или вставке других задач. Идентификатор `id` уникально определяет запись в предметной области независимо от перестановок и фильтрации.
- **Почему `getTaskStats` возвращает число, а не строку с процентом:** Функция бизнес-логики вычисляет чистые числовые метрики для дальнейших программных вычислений и сравнений. Округление и добавление знака `%` (`progress.toFixed(1) + '%'`) относятся к слою форматирования вывода (представления).
- **Какие объекты копируются при изменении задачи:** При операциях изменения создаётся новый массив (через спред или метод `map`). Для целевой задачи создаётся новый объект через `{ ...task, ...changes }`. Неизменённые задачи переиспользуются по существующим ссылкам (структурное разделение данных).

## 9. Вывод

В ходе практической работы разработана модульная сервисная логика без привязки к интерфейсу. По сравнению с ПР1 данные структурированы в виде массива объектов, а операции вынесены в чистые функции с возвратом предсказуемых объектов результата (`ok: true/false`).

Иммутабельность данных проверена тестами с `Object.freeze()`: ни одна операция добавления, удаления или редактирования не изменяет переданный массив и не мутирует существующие объекты задач. Выявлена ключевая роль строгого возврата новых ссылок при точечном обновлении записей (`map`), что исключает побочные эффекты в логике приложения.
